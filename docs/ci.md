# CI usage

program-design runs headless in CI: hand a manifest to `check`, branch on the
exit code. No daemon, no browser, no API key.

## Exit codes

| Code | Meaning |
|---|---|
| `0` | no ABSENT verdicts — no divergence between the claims and the code |
| `1` | at least one ABSENT verdict — a divergence |
| `2` | tool error (bad manifest, not a Next.js repo, corrupt graph, etc.) |

UNDETERMINED verdicts do **not** fail the build. Only a provable ABSENT does.

## `--json`

Every read command supports `--json` for machine consumption. `check --json`
emits:

```json
{
  "summary": {
    "confirmed": 5,
    "absent": 1,
    "undetermined": 2,
    "unverifiable": 1,
    "coverage": 0.875
  },
  "verdicts": [ /* ClaimVerdict[] */ ]
}
```

`report --json`, `patterns --json`, `status --json`, `doctor --json`, and
`export mermaid` (to stdout) round out the agent/CI surface.

## GitHub Actions example

```yaml
name: verify-claims
on: [pull_request]

jobs:
  claims:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
      - run: npm ci
      # claims.json is committed, or generated by your agent step.
      - name: Verify claims against the code
        run: npx program-design check --manifest claims.json --json
        # exit 1 (divergence) fails the job; exit 2 (tool error) also fails.
```

To capture the verdicts as an artifact even on failure:

```yaml
      - name: Verify
        id: verify
        continue-on-error: true
        run: npx program-design check --manifest claims.json --json > verdicts.json
      - uses: actions/upload-artifact@v4
        with:
          name: verdicts
          path: verdicts.json
      - name: Fail on divergence
        if: steps.verify.outcome == 'failure'
        run: exit 1
```

## Troubleshooting

- Run `npx program-design doctor --json` and attach the output to any issue.
- A `2` exit with a `[manifest-invalid]` error means the manifest shape is wrong —
  see [claim-manifest.md](claim-manifest.md).
- A `2` exit with `[not-a-nextjs-repo]` means no `app/`/`pages/` dir and no `next`
  dependency was found at `--repo` (default cwd).
- See the full [error catalog](errors.md).
