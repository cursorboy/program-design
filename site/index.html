the problem

You can't review code you can't read.

People build real products with AI agents now. The agent says "done — I added login with rate limiting" and… sometimes it's true. Sometimes the rate limiting is missing, the email is logged but never stored, or the route it described doesn't exist.

Catching that means reading the code — which is the one thing you can't do. A second AI reviewer doesn't fix it either: a second model hallucinates just like the first.

program-design is a different kind of answer: a deterministic reader. It parses the raw source into a facts graph and checks claims against it mechanically. The LLM only translates in and narrates out — fenced by receipts. It never renders the verdict.

"You don't have to trust the tool. You can open the line of code it points at."

Three-state claim checker

A claim becomes a query over the graph. The verdict — CONFIRMED, ABSENT, or UNDETERMINED — is computed deterministically against a versioned pattern allowlist. The model never decides.

Three verdicts. No fourth option.

docs/what-it-verifies.md

Most tools fail by overclaiming. This one is built around the refusal to.

✓ CONFIRMED

The claimed thing is in the code, with a file:line receipt you can open — in your editor or right in the report.

"Found it. Here's the line."

✕ ABSENT

Provable absence. Every ABSENT records its search scope — which conventions, directories, and matchers were checked.

"Looked everywhere it could legally be. Not there."

? UNDETERMINED

Dynamic dispatch, a URL built at runtime, an unsupported pattern — the tool says "I can't safely confirm this" and shows the exact code that defeated it.

Never dressed up as a yes or a no.

the Claude Code skill

Verification at claim time, inside your session.

When your agent says "done", the skill translates that claim into a structured manifest, runs the deterministic verifier in clean context, and presents the verdict table verbatim — it is not allowed to soften an ABSENT.

Zero config, no API keys: the narrator runs inside the Claude Code session you already have. State lives in ~/.program-design/ — your repo is never polluted.
